## Comportements corrigés

« Passer » ouvre immédiatement l'application sans compte depuis chacune des trois pages. Le bouton ne se contente plus d'avancer jusqu'à la dernière page. Le parcours Suivant conserve le choix de la démo à la fin, et l'animation de plume reste en place.

Un bouton soleil/lune permet de changer l'apparence dès l'onboarding. Dans Profil → Apparence, choisir Système, Clair ou Sombre. Ce choix est mémorisé sur l'appareil, appliqué aux écrans, cartes, formulaires et à la navigation, sans réinitialiser les données ou les formulaires. Le mode Système suit aussi les changements d'apparence dans le navigateur.

## Migration des dépendances

Expo est déclaré en `~57.0.26` et verrouillé à `57.0.26`. React est en `19.2.3`, React Native en `0.86.3`, TypeScript en `~6.0.3`. Les modules Expo, Reanimated et Worklets suivent la matrice du SDK 57. Le lockfile utilise des URL publiques npm et conserve les contrôles d'intégrité. Aucun `--force` ni `--legacy-peer-deps` n'est nécessaire.

Adaptations des changements des SDK 55, 56 et 57 :

- Remplacement du module retiré `expo-av` par `expo-audio` pour la lecture des rappels. Le lecteur est libéré au démontage. Aucune permission micro ni lecture en arrière-plan supplémentaire n'est activée.
- Thème de navigation importé via `expo-router/react-navigation` ; retrait de la dépendance directe inutilisée à React Navigation.
- Remplacement de l'API de style supprimée `absoluteFillObject`, retrait des anciens paramètres New Architecture/edge-to-edge et de `baseUrl` TypeScript.
- Activation iOS de Scene support via `expo-build-properties`, requise pour SDK 57 avec Xcode 27.
- Contrôle `mobile:check` mis à jour : il refuse toujours une installation absente, un SDK installé différent du lockfile, une mauvaise racine ou des URL privées Replit.

Les identifiants de l'application, le backend et les workflows de publication Replit existants ne sont pas modifiés. Les champs Expo/Apple injectés par Replit lors d'une publication doivent rester ceux du projet qui a déjà publié avec succès.

## Récupérer dans Replit

Utiliser le Shell à la racine mobile contenant `package.json`, et arrêter le workflow avec le bouton Stop avant l'installation.

```sh
git status
```

Si l'état est propre, exécuter une ligne à la fois :

```sh
git fetch origin
git switch feat/onboarding-safety-paywall
git pull --ff-only origin feat/onboarding-safety-paywall
npm ci
npm run mobile:check
```

Si des modifications locales existent, les conserver avant ces étapes :

```sh
git stash push -u -m "replit-before-sdk57"
git stash list
```

Le stash est local ; les fichiers ignorés, notamment `.env`, n'y sont pas inclus. Conserver les secrets dans Replit. Ne pas remettre automatiquement un ancien stash entier par-dessus cette migration. Si `pull --ff-only` refuse une divergence, garder le message et comparer les commits ; ne pas forcer ni effacer le travail local.

`npm ci` réinstalle les versions du lockfile et remplace `node_modules`. Il ne supprime pas le code. Le contrôle doit annoncer **Expo 57.0.26 (SDK 57)**. Ne pas réexécuter les anciennes commandes SDK 54 ni supprimer le lockfile.

Cliquer ensuite sur **Run**, puis rouvrir le preview. Sur iPhone avec Expo Go SDK 57, utiliser le **nouveau QR code/lien** de ce serveur ; un ancien lien ou un serveur resté actif peut encore pointer sur l'ancienne version.

## Preview Replit et Expo Go

Le workflow Replit natif et ses ports sont conservés. La version d'Expo Go du simulateur intégré est fournie par Replit : le code de ce dépôt ne peut pas la mettre à jour. Si ce simulateur annonce encore SDK 54, demander/choisir un runtime SDK 57 côté Replit ou utiliser le preview web du même projet en attendant.

Pour le preview web, garder le backend en marche et lancer dans un autre Shell :

```sh
npm run preview:web
```

Ouvrir le port **8083** dans l'outil Preview/Ports de Replit (déjà déclaré dans `.replit`, port externe 3001). Cette commande utilise les mêmes écrans et le même code ; elle ne crée pas un second projet. Les variables Replit habituelles restent nécessaires pour les écrans connectés au backend. Le mode sans compte et la démo fonctionnent localement.

Expo Go et le navigateur permettent de tester la navigation, les thèmes, l'onboarding et les données de démonstration. Les achats RevenueCat et les rappels natifs restent volontairement indisponibles dans ces environnements : les valider dans **un nouveau build iOS**, avec la configuration Apple/RevenueCat décrite dans le [guide de livraison](REPLIT-TESTFLIGHT-20261006.md).

## Validation effectuée

- Installation propre avec `npm ci`, contrôle des URL publiques et du SDK avec `npm run mobile:check`.
- TypeScript et 25 tests de logique/stockage/build.
- `expo install --check` : dépendances à jour ; Expo Doctor : **21/21 contrôles réussis**.
- Exports de production JavaScript/Hermes iOS et Android.
- Prebuild iOS `--no-install` dans une copie isolée, avec génération du manifeste Scene support.
- Parcours navigateur au format téléphone : Passer sur les trois pages, thèmes clair/sombre/système, mémorisation après rechargement, démo, retour invité, formulaire avec prix à virgule, calendrier et paywall. Aucune erreur JavaScript non interceptée pendant ces parcours.
- Manifeste servi pour iOS : `sdkVersion: 57.0.0`.

Ces contrôles n'incluent pas une compilation/signature Xcode, une session dans le simulateur Replit distant ou un essai sur l'iPhone de Laure. Ils ne constituent pas une garantie d'absence de bug natif. La première ouverture avec la plume, les permissions, les achats et la livraison réelle des notifications sont à confirmer sur le prochain build TestFlight avant fusion/publication définitive.

## Retour à la version de preview SDK 54

Après sauvegarde des éventuels changements locaux et arrêt du workflow :

```sh
git fetch origin
git switch backup/features-sdk54-20261006-7368b6d
npm ci
```

Puis Run. Ce retour rétablit la source SDK 54 ; il ne la rend pas compatible avec Expo Go SDK 57 sur l'iPhone. Il ne modifie pas main ni le build TestFlight déjà envoyé.
